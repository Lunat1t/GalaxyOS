# Galaxy — контекст и память для LLM в разработке

Galaxy помогает Codex и другим coding agents разобраться в репозитории: находит относящиеся к задаче файлы, инструкции и проверенный опыт, собирает из них компактный контекст и поддерживает проверку результата.

**Текущая версия кода:** `3.2.1-alpha.2-contextbench`  
**Ближайшая продуктовая цель:**
Galaxy 4.0 - Стабильное ядро 

Galaxy 5.0 - простое подключение к Codex, полезный контекст, статичные специализированные агенты, оркестратор и проверяемые предложения по улучшению навыков.  
**Техническая цель ядра:** довести Galaxy Core до надёжного и измеренного уровня; текущие ограничения описаны в [архитектуре](docs/core-architecture.md).  
**Долгосрочное направление:** рабочее пространство Galaxy с проектами, заметками и совместной работой. Это будущее направление, не объём ближайшего релиза.

## Как работает Galaxy

1. Galaxy строит карту проекта и замечает изменения.
2. Для конкретной задачи он ищет подходящие файлы, инструкции и связанные знания.
3. Он собирает ограниченный контекст с указанием источников.
4. Codex или другой агент использует этот контекст для работы.
5. Там, где настроены проверки, Galaxy сохраняет их результаты и помогает отличить проверенный итог от слов агента.

Коротко: **Galaxy помогает LLM быстрее найти нужное в проекте и использовать это при выполнении задачи.** Он не заменяет Codex и не гарантирует правильное решение.

## Подключение к Codex

В этой версии есть два локальных способа подключить Galaxy к работе с Codex. Это не один универсальный плагин:

1. **Передать контекст вручную.** Скрипт `codex_context.py` собирает контекст репозитория и проектную память. Вывод можно передать Codex вместе с задачей.
2. **Подключить заметки через MCP.** Сервер `system/mcp/obsidian_bridge.js` предоставляет `get_note`, `append_log` и `search_vault` для Obsidian-хранилища. Это мост к заметкам, а не инструмент Galaxy `get_context`.

### Передать Codex контекст задачи

Запустите из корня репозитория:

```bash
python codex_context.py build "исправить обновление токена" --root . --budget-tokens 8000
```

Скрипт выводит пакет контекста в JSON. Проверьте, что в нём нет лишних или чувствительных данных, затем передайте его Codex вместе с задачей. Чтобы сохранить решение из чата, используйте `remember`; исправить или забыть память можно командами `correct` и `forget`. Полный список параметров:

```bash
python codex_context.py --help
```

Это явная передача контекста: текущая версия не регистрирует `get_context` как MCP-инструмент Codex.

### Подключить локальный MCP-мост заметок

Пример конфигурации находится в `system/mcp/mcp_config.json`. Он подключает Node.js-мост к Obsidian-хранилищу. Нужен Node.js 18+. По умолчанию мост работает внутри выбранного хранилища; другой путь задаётся через `VAULT_PATH`. Описание инструментов и запуска: [`system/mcp/README.md`](system/mcp/README.md).

Проверьте разрешения и путь к хранилищу перед использованием. Этот мост не предоставляет облачную авторизацию и не подключает Galaxy Context Compiler к Codex автоматически.

## Что уже измерили

- **Синтетический поиск:** среди 10 000 искусственных документов ускоренный поиск занял медианно 23 мс, полный перебор — 122 мс (примерно в 5,2 раза быстрее). Средний Recall@20 — 95,6%, минимум — 85%. Это сравнение двух способов поиска внутри Galaxy, а не Codex с Galaxy против Codex без него.
- **Локальный кэш контекста:** на проекте из 152 файлов повторная сборка заняла медианно 20,8 мс вместо 100,7 мс без попадания в кэш (примерно в 4,8 раза быстрее). Это только скорость локальной сборки контекста.
- **SWE-bench пилот:** три задачи, по одной попытке в каждом варианте. Успех совпал во всех трёх парах: Galaxy не изменил исход. В одной задаче с Galaxy использовано примерно на 300 тысяч токенов больше, в другой — примерно на 99 тысяч меньше. Такой малой выборки недостаточно, чтобы заключить, что Galaxy улучшает результат или экономит токены.
- **ContextBench и RepoBench-R:** в проекте есть адаптеры и команды для запуска, но завершённых независимых итогов, подтверждающих качество Galaxy, пока нет.

Подробности о методике и ограничениях приведены в [источниках по проверке продукта](docs/sources/galaxy-superapp/05-product-validation.md) и [заметках о текущем состоянии](docs/sources/galaxy-superapp/01-current-galaxy.md).

## Alpha 19: проверка целостности доказательств

`require_evidence` проверяет собственный журнал Galaxy с успешными командами
проверки и сверяет сохранённый лог с его контрольной суммой. Одной строки
доказательства от агента недостаточно. При повторном открытии завершённый запуск
проверяется снова: если лог отсутствует или изменён, статус `DONE` отзывается.
Правило, включённое после создания запуска, проверяется перед его выполнением.
Эпизод опыта считается подтверждённым, только если логи команд всё ещё проходят
проверку журнала. Сверяйте доступность этой экспериментальной функции с текущей версией кода.

## Alpha 18: правила доказательств и проверки

В плане выполнения можно указать `task_type`: `bugfix`, `feature` или `general`.
Каждый агент получает `verification_contract` с критериями приёмки,
детерминированными командами и действующими правилами проекта. Для каждой
проверки сохраняются код завершения, путь к логу и хеш вывода. Успешная команда
добавляет краткий лог к доказательствам узла; неуспешная — лог ошибки к эпизоду.
Заявление `PASS` не отменяет провал команды.

Повторяющиеся ошибки с доказательствами могут создать **кандидатное** правило
с указанным `task_type`, видом проверки и ID эпизодов-источников. `rule-eval`
повторно проверяет размеченные примеры; для `rule-promote` нужны безошибочный
повтор и указанный проверяющий. Действующее `require_command` отклоняет план,
если в нём нет последующей проверки с нужной командой. `require_evidence`
не позволяет успешно завершить QA-узел без записанных доказательств.
`rule-disable` отключает правило.

Это ограниченная первая версия. Она не выводит безопасные команды проверки из
обычного текста, не подтверждает личность проверяющего в CLI, не создаёт
конфигурации CI и не доказывает, что агенты реже повторяют ошибки. См.
`docs/verification-alpha.18.md`.

## Alpha 17: перенос опыта между задачами

Завершённые узлы DAG сохраняются как эпизоды с указанием источника. Позже
временный агент может получить подходящие эпизоды от другой роли или модели через
`ContextCompiler`. На опыт выделяется не более 10% эффективного бюджета (максимум
900 токенов); в пакет включаются результат, исходный запуск и узел, уверенность и
доказательства. Добавление или отзыв эпизода сбрасывает кэш пакета. Для хранения
и поиска не требуется модель.

```bash
python galaxy.py experience-record "fix token rotation" "auth tests passed" \
  --project demo --role Earth --agent-id earth-1 --run-id run-1 --node-id auth \
  --outcome success --lesson "Test token rotation before deployment" \
  --evidence "pytest tests/test_auth.py passed"
python galaxy.py experience-search "verify token rotation" --project demo --role Moon
python galaxy.py context-build "verify token rotation" --project demo --role Moon
```

Если репозиторий находится в другом месте, укажите для всех трёх команд один и
тот же `--root /path/to/repository`. Команда `experience-retract EXP-...`
убирает ошибочный эпизод из будущего контекста. Для доверенных локальных
пользователей доступны личные и командные области, но аргументы идентичности CLI
не являются аутентификацией. Не выставляйте их как защиту многопользовательского
сервиса.

Два независимых успешных запуска с подтверждающими доказательствами и одинаковым
выводом создают проверяемую **кандидатную** инструкцию. Противоречащая ошибка
блокирует её создание. Автоматического переноса в подтверждённые знания проекта
нет.

`experience-eval ordered-tasks.json --repo /path/to/repository` изолированно
повторяет связанные размеченные задачи и сравнивает поиск прежних эпизодов,
примерный объём токенов пакета и время сборки с вариантом без опыта. Это замер
только поиска. Чтобы проверить пользу Codex с Galaxy, нужно выполнить обе версии
на отложенной серии задач и измерить проверенный успех, все входные/выходные
токены модели, общее время и повторные ошибки. Схема и протокол описаны в
`docs/continuity-alpha.17.md`.

Инструмент `experience-bench` предлагается как следующий шаг оценки: он должен многократно сравнивать Codex в трёх вариантах: только
репозиторий, найденные исходные эпизоды и ограниченный собранный Galaxy-пакет.
Он записывает критерии, при необходимости проверенные оценки смысла и
происхождения, пользу/вред памяти и расход токенов Codex из JSONL:

```bash
galaxy experience-bench tasks.json --repo /path/to/repository --out-dir benchmarks/run-01 --repetitions 3
```

Этот калибровочный запуск работает только на чтение и не оценивает успешность
изменения кода. Перед использованием проверьте наличие этой команды в версии,
с которой работаете; набор задач и формат отчёта нужно зафиксировать заранее.

> Текущая версия работает без графического интерфейса: здесь нет TUI,
> веб-сервера Orbit, панели SaaS или интерфейса в стиле Obsidian.

## Проверка качества кода и расширение поиска

### Связи между классами и RepoBench-R

World Model может находить связи наследования классов, если базовый класс однозначно определён в репозитории. Дополнительный режим поиска в один переход берёт 15 лучших файлов и добавляет прямо импортируемые модули и файлы родительских классов. Результат остаётся ограничен 15 файлами и бюджетом 20 000 токенов.

```bash
galaxy contextbench-graph-compare data/contextbench_verified.parquet \
  --repo /path/to/django --evaluate \
  --out-dir benchmarks/django-one-hop-graph
```

Команда сохраняет сравнение обычного поиска и режима в один переход. Дополнительный файл не считается правильным ответом, пока это не подтвердит внешний оценщик.

Для RepoBench-R подготовьте JSONL с полями `repo_name`, `file_path`, `context`, `import_statement`, `code` и `gold_snippet_index`:

```bash
galaxy repobench-r-run data/repobench-r-python-cff-test-easy.jsonl \
  --semantic-mode exact --out-dir benchmarks/repobench-r-python-cff-test-easy
```

Отчёт включает Accuracy@1/5/10, MRR и скорость. `next_line` не используется как запрос. Данные RepoBench-R не входят в репозиторий; получите официальный набор и соблюдайте его лицензию.

### Сравнение точного и ускоренного поиска

`contextbench-compare` запускает два режима на одинаковых задачах с одинаковыми ограничениями. Он сообщает, какие файлы изменились, насколько похожи результаты, сколько времени занял поиск и сколько векторов было обработано. Полноту и точность подсчитывает только официальный оценщик ContextBench.

```bash
galaxy contextbench-compare data/contextbench_verified.parquet \
  --repos-dir /path/to/repos --limit 50 --evaluate \
  --out-dir benchmarks/contextbench-ann-verified-50
```

Поддержка запуска есть, но завершённых внешних результатов в проекте пока нет: необходимы официальный набор данных, снимки репозиториев и оценщик.

### Ускоренный семантический поиск

В больших индексах Galaxy отбирает ограниченную группу кандидатов, затем точно пересчитывает сходство только для них. Для небольших наборов применяется полный поиск. Режим и объём обработки записываются в трассировку.

```bash
galaxy attention-build "исправить аутентификацию" --root /path/to/repo --semantic-mode auto
galaxy attention-build "исправить аутентификацию" --root /path/to/repo --semantic-mode exact
galaxy attention-build "исправить аутентификацию" --root /path/to/repo --semantic-mode ann
```

На искусственном наборе из 10 000 документов ускоренный поиск занял около 23 мс против 122 мс при полном переборе. Средний Recall@20 составил 95,6%, минимум — 85%. Это сравнение способов поиска внутри Galaxy, а не Codex с Galaxy и без него. Подробная оговорка приведена в разделе [измерений](#что-уже-измерили).

### Кэш готового контекста

Galaxy сохраняет ограниченный кэш собранных пакетов по проекту. При повторном запросе кэш позволяет пропустить часть анализа и сборки. Если меняется код или память, пакет перестраивается. На локальном проекте из 152 файлов замер показал 20,8 мс при попадании в кэш и 100,7 мс без него. Это только время сборки контекста, не полная скорость работы Codex.

## Поиск по репозиторию: ContextBench

Galaxy умеет подготовить предсказания о том, какие файлы важны для описанной задачи. Официальный ContextBench оценивает выбранные файлы по размеченным ответам.

Подготовьте локальные копии репозиториев, содержащие нужные базовые коммиты, и официальный набор данных. Для Parquet может понадобиться `pyarrow`.

```bash
python galaxy.py contextbench-run data/contextbench_verified.parquet \
  --repos-dir /path/to/repos \
  --limit 10 --token-budget 10000 --max-files 20 \
  --out benchmarks/contextbench-predictions.jsonl
```

Чтобы выполнить официальную оценку, установите ContextBench и запустите:

```bash
python -m contextbench.evaluate \
  --gold data/contextbench_verified.parquet \
  --pred benchmarks/contextbench-predictions.jsonl \
  --out benchmarks/contextbench-scores.jsonl
```

Этот адаптер проверяет выбор файлов. Он не оценивает точные строки кода, успешность исправления или качество полного запуска агента. Итоговых независимых оценок Galaxy пока нет.

## Как устроена сборка контекста

Большое окно модели само по себе не гарантирует, что модель заметит важные детали. Galaxy сначала широко ищет кандидатов, затем выбирает ограниченный и объяснимый набор материалов.

```text
Репозиторий и заметки проекта
        ↓
Карта структуры и память
        ↓
Поиск по словам, смыслу и связям файлов
        ↓
Проверка уверенности и актуальности
        ↓
Короткие фрагменты с источниками
        ↓
Пакет контекста для Codex или другой модели
```

### Способы поиска

Attention Engine сочетает BM25-поиск по тексту, поиск по именам файлов и символов, семантическое сходство и связи проекта. Система объясняет, почему кандидатный файл попал в результаты.

```bash
python galaxy.py attention-build \
  "изменить ротацию токенов" \
  --root /path/to/repo --project demo
```

### Фрагменты с доказательствами

Galaxy старается передавать не начало каждого выбранного файла, а строки вокруг подходящих символов и совпадений. Для каждого файла указываются роль, причины выбора, оценки поиска и примерная цена в токенах.

### Бюджет контекста

При `--budget-tokens 0` Galaxy подбирает размер контекста по сложности задачи. Бюджет распределяется между файлами, памятью, связями проекта и инструкциями. Явный положительный бюджет становится жёстким ограничением.

### Небольшой проект

Если небольшой проект целиком помещается в заданные пределы, Galaxy может использовать стратегию полного контекста. Для крупных проектов используется гибридный поиск. Цель — не применять поиск ради самого поиска, а дать модели полезные материалы.

### Фильтр кандидатов и диагностические оценки

Кандидат может быть включён, отложен для рассмотрения или исключён. Основное решение детерминировано и проверяемо. Диагностические поля вроде `coverage_signal`, `noise_signal` и `selection_confidence` помогают разработке, но не являются измеренной точностью ответов модели.

### Сборка пакета

```bash
python galaxy.py context-build \
  "изменить архитектуру аутентификации" \
  --root /path/to/repo --project demo --budget-tokens 0
```

Пакет может включать выбранные фрагменты, связи, память, инструкции `AGENTS.md`/`CLAUDE.md`, прогноз влияния изменений и сведения о неопределённости.

## Другие возможности ядра

### Структура проекта и её изменения

```bash
python galaxy.py world-sync --root /path/to/repo --project demo
python galaxy.py world-drift --root /path/to/repo --project demo
```

World Model хранит файлы, символы и поддерживаемые связи. `world-drift` показывает структурные изменения; это не оценка качества кода.

### Прогноз затронутых частей

```bash
python galaxy.py future-impact \
  "изменить модель сессии" \
  --root /path/to/repo --project demo --seed src/auth.py
```

Future Graph строит структурный прогноз и явно содержит неопределённость. Это не доказательство реального поведения во время выполнения программы.

### Проверка памяти

```bash
python galaxy.py brain-reconcile --root /path/to/repo --project demo
python galaxy.py brain-reconcile --root /path/to/repo --project demo --apply
```

Устаревшие и противоречивые сведения остаются доступными для аудита, но исключаются из обычного поиска активной памяти. Изменения применяйте только когда понимаете их последствия.

## Запуск из репозитория

Для проверки доступных команд выполните из корня проекта:

```bash
python galaxy.py --help
python galaxy.py doctor
```

Перед запуском контекстных команд укажите путь к проекту и задачу, например:

```bash
python galaxy.py context-build "найти обработчик загрузки изображений" --root /path/to/repo --project demo
```

Для передачи Codex контекста используйте `codex_context.py`, описанный выше. В этой версии нет подтверждённого установщика `pipx` или команды `galaxy mcp-server`.

## Текущие ограничения

Galaxy 3.2.1 alpha — это локальное ядро и инструменты для подготовки контекста. В этой версии нет готового IDE-интерфейса, TUI, веб-сервера Orbit, панели SaaS или интеграции с интерфейсом Obsidian. См. [архитектуру ядра](docs/core-architecture.md) и [план Galaxy 5.0](docs/galaxy-v5-roadmap.md).
