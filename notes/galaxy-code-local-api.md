# Локальный API Galaxy Code

**Контракт:** v1.2.5. Операции проектов, задач и Run реализованы в `galaxy_core/local_api.py`; данные Run хранятся отдельно в `runs.sqlite3`.

## Зачем нужен этот слой

Next.js отвечает за веб-интерфейс. Python-ядро Galaxy остаётся владельцем проектов, настроек, задач, памяти и файлов данных. Браузер вызывает серверные маршруты Next.js; они передают запросы локальному Python-сервису. Так правила и записи не дублируются в JavaScript, а внутренний ключ сервиса не попадает в браузер.

```text
Браузер → Next.js (UI и серверные маршруты) → локальный Python API → существующие хранилища
```

В первом варианте приложение работает на одном компьютере. Удалённый доступ, синхронизация и мобильное подключение сюда не входят.

## Границы и безопасность

- Python API слушает только loopback-интерфейс (`127.0.0.1` или `::1`), не все сетевые интерфейсы.
- Браузер обращается к API через Next.js server routes и не знает адрес/ключ внутреннего сервиса.
- Next.js вызывает Python API с секретом запуска из файла `local-api-<port>.token` в пользовательской папке данных Galaxy. Для разных портов используются разные файлы. Файл создаётся с правами владельца, если ОС их поддерживает, и удаляется при остановке сервиса. Next.js читает его только на сервере; секрет нельзя отправлять браузеру, писать в журнал или сохранять в настройках проекта.
- Python API проверяет этот секрет на каждом запросе. Маршруты чтения проектов и данных тоже требуют авторизации.
- Маршруты Next.js проверяют, что изменяющие запросы пришли с origin текущего приложения; cookie-сессию защищают от CSRF.
- API принимает действия только для зарегистрированных `project_id`. Отдельная операция добавления проекта может зарегистрировать введённый пользователем существующий путь; API не предоставляет произвольное чтение файлов по пути.
- Ошибки не возвращают секреты, переменные окружения или содержимое файлов. Credentials провайдеров через этот контракт не передаются.
- CORS не открывается для произвольных сайтов. Удалённое прослушивание и публичная авторизация потребуют отдельного решения.

## Формат

- Префикс маршрутов: `/api/v1/`.
- Запросы и ответы — JSON в UTF-8. Имена полей — `snake_case`, ID проектов и задач сохраняют текущий формат.
- Даты — UTC ISO 8601.
- Успешное создание возвращает `201`; чтение и изменение — `200`.
- Ошибка имеет единый вид: `{"error":{"code":"...","message":"..."}}`. Текст для пользователя не содержит tracebacks.
- Изменение настроек — частичное; неизвестные поля и значения отклоняются в Python-ядре по существующей валидации.

## Первый набор маршрутов

| Маршрут | Назначение |
| --- | --- |
| `GET /api/v1/health` | Проверить, что локальный сервис запущен и отвечает |
| `GET /api/v1/projects?limit=20` | Список недавних проектов и ID активного проекта |
| `POST /api/v1/projects` | Зарегистрировать существующий путь проекта; тело `{ "path": "...", "name": "..." }` |
| `POST /api/v1/projects/{project_id}/open` | Сделать зарегистрированный проект активным |
| `GET /api/v1/projects/{project_id}` | Прочитать сведения проекта |
| `GET /api/v1/projects/{project_id}/settings` | Прочитать сохранённые настройки |
| `PATCH /api/v1/projects/{project_id}/settings` | Частично обновить настройки с проверкой Python-ядра |
| `GET /api/v1/projects/{project_id}/tasks?limit=20` | Список задач проекта |
| `POST /api/v1/projects/{project_id}/tasks` | Сохранить запрос в очереди; тело `{ "request": "..." }` |
| `GET /api/v1/tasks/{task_id}` | Прочитать задачу и её статус |
| `POST /api/v1/projects/{project_id}/tasks/{task_id}/run` | Запустить Codex в отдельной Git worktree или копии папки без Git |
| `GET /api/v1/runs/{run_id}` | Прочитать статус Run |
| `GET /api/v1/runs/{run_id}/events?after=0` | Прочитать журнал событий после указанного номера |
| `POST /api/v1/runs/{run_id}/cancel` | Остановить активный процесс Codex |

Создание задачи сохраняет статус `queued`. Запуск пока доступен только для Codex. Next.js опрашивает журнал событий; секрет локального API остаётся на сервере.

## Что ещё предстоит в этапе 2

Проверки, diff, привязка результата проверки к состоянию файлов, подтверждение пользователя и безопасное применение diff пока не реализованы. События Run уже append-only и имеют возрастающий `sequence`; при перезапуске локального сервиса незавершённый Run отмечается как прерванный.

## Реализация

Существующий `ProjectRegistry` — первая реализация операций проектов и задач. HTTP-слой вызывает его, не создавая вторую SQLite-схему и не меняя пользовательские данные. Сервис использует стандартный Python HTTP server и запускается командой `galaxy serve`. Next.js-клиент, его серверный proxy-маршрут и совместный запуск процессов ещё не реализованы.
