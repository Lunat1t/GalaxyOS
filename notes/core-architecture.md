**Статус:** этап 0 описан; этап 1 в работе. Версия 1.0.9 добавляет очередь задач в Project; агентное выполнение ещё не подключено. Этапы и критерии готовности заданы в разделе 48 плана `/home/bah/Downloads/Galaxy_Code_Detailed.md`.

## Первый сквозной путь

```text
Project → Task → Agent + Provider + Harness → Run → проверки и diff
                                                → Approval → результат и опыт
```

В первом рабочем срезе пользователь открывает локальный Project через TUI «Рабочая область», поручает Task одному Agent с Codex CLI и видит события Run. Выполнение работает в ограниченном рабочем месте. Перед применением изменений пользователь получает проверки и конкретный Git diff. Решение и его основание записываются в журнал. Данные Run могут стать опытом только с явным происхождением и статусом проверки.

## Целевые границы компонентов

| Компонент | Ответственность | Состояние сейчас |
| --- | --- | --- |
| Project и TUI | Выбор каталога, проектные настройки, задачи, диалог, статусы, diff и подтверждение | Реестр, команды и экран выбора проекта добавлены; задачи и агенты ещё не подключены |
| Agent и Worker | Устойчивый профиль агента и ограниченный временный исполнитель | Есть legacy `galaxy_core/agents/`; контракт предстоит пересмотреть |
| Task, Run и Approval | Запрос, исполнение, журнал событий, проверка и решение пользователя | Есть механизмы `galaxy_core/engine/`; повторное использование требует проверки контрактов |
| Provider и Harness | Единый контракт вызова; сборка прав, инструментов, окружения и контекста на задачу | Есть legacy `galaxy_core/providers/`; новые адаптеры ещё не реализованы |
| Managed Brain | Записи памяти, статусы, ссылки, provenance и история исправлений | Существует в `galaxy_core/brain/`; данные сохраняются |
| Markdown vault | Читаемые заметки, ссылки и поиск; SQLite индекс производный | Существует в `galaxy_core/vault/`; Markdown остаётся источником |
| Goals и experience | Цели и эпизоды с проверяемым происхождением | Существуют в `galaxy_core/brain/`; нужна привязка к Task/Run |

Логическая схема, связи и владельцы данных описаны в [модели данных Galaxy Code](galaxy-code-data-model.md). Текущие хранилища и порядок переноса — в [инвентаризации и карте миграции](galaxy-code-migration-map.md). Первый сценарий и формат журнала — в [контракте Run](galaxy-code-run-contract.md). Эти документы задают целевые контракты, а не утверждают совместимость legacy кода с новым циклом.

## Память и данные

Сохранять записи BrainStore, Markdown vault, цели, опыт и историю в существующих форматах до инвентаризации. Миграция должна иметь резервную копию, сопоставление ID и источников и способ отката. Поиск памяти не подтверждает истинность найденного: подтверждённые, предполагаемые, устаревшие и отозванные сведения остаются различимыми. CLI-флаги идентичности не являются авторизацией для нескольких пользователей.

## Контекст для задачи

Планируемый Context Builder выбирает связанные с Task файлы, проектные правила, ошибки проверок и записи памяти; фиксирует список источников и ограничения. Он не строит глобальную модель репозитория и не запускает watcher. World Model, Attention Engine, прежний Context Compiler, Kernel Projector/Watcher и MCP get_context остаются удалёнными. См. [решение об удалении](context-retirement.md).
