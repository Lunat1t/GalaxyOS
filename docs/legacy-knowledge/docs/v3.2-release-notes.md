# Galaxy 3.2.0-alpha.1 — Attention Engine

## Why this release exists

3.0 made project context explicit. 3.1 made it living and predictive. 3.2 changes the question from:

> Which files match this task?

into:

> What is the smallest evidence-rich project view that gives an executor enough information without drowning it in unrelated context?

## New subsystem

`galaxy_core/attention/`

Pipeline:

```text
task
 ↓
wide retrieval
 ├─ BM25/content
 ├─ lexical path/symbol
 └─ portable semantic similarity
 ↓
structural expansion
 ├─ dependency graph
 └─ Future Graph
 ↓
gatekeeper
 ↓
evidence extraction
 ↓
adaptive budget packer
 ↓
selected context
```

## Design choices

- Offline and dependency-free by default.
- No requirement for a vector service.
- No hidden external LLM calls during normal retrieval.
- Small projects may use bounded full context.
- Large projects use hybrid attention.
- Probabilistic gating is an optional bounded refinement, not authority.
- Retrieval diagnostics are labelled as heuristic signals.

## CLI

```bash
python galaxy.py attention-build "task" --root /repo --project demo
python galaxy.py context-build "task" --root /repo --project demo --budget-tokens 0
```

`--budget-tokens 0` activates adaptive budgeting.

## Tests added

3.2 regression coverage verifies:

1. relevant evidence can be extracted from the middle of a long file;
2. dependency/Future-Graph expansion can pull connected tests;
3. a genuinely small project can use bounded full context;
4. adaptive budgets distinguish localized and architectural work;
5. Attention Engine diagnostics and evidence appear in final Context Packets.

## Known alpha limits

- Semantic scoring uses Galaxy's portable hashed embedder by default, not a neural code embedding model.
- BM25 is rebuilt in-memory per attention run; persistent retrieval indexes are a later optimization.
- Evidence extraction is line-window based, not AST-block/dataflow aware yet.
- Graph quality is bounded by the current World Model dependency extractors.
- Attention quality signals are internal diagnostics, not benchmarked correctness metrics.
- Runtime/API/database/service-level retrieval is not yet first-class.
